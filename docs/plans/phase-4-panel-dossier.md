It is the only proposal with no last place, and the only one whose oracles are mostly non-tautological BY CONSTRUCTION. Three of its four wave-1 checks run two independent producers against each other over artifacts this phase did not author: `renderGreenBar(paper, {chain:'A', formLines:66})` — verified at printer1403.ts:718, with rule 3's trailing-blank trim and rule 2's stop-at-highest-printed-line — asserted equal to the trimmed \f-joined `paginate()` output over three already-frozen page goldens; `restrike(chainGlyph(c,'A'),'H') === chainGlyph(c,'H')` over all 64 codes, derived from the shipped device rather than a transcribed table (and the bijection genuinely holds: charset.md §5's five duals `& ⌑ % # @` → `+ ) ( = '`, none of the H glyphs on the A set, and §5.1 makes `?` → `&`/`+` collide identically on both chains); and a card-face golden cross-derived from `punchMask` so the path string and the punch table must agree for two unrelated reasons. Its design rule — no number is computed in a file that touches the DOM — is the only mechanism anyone proposed that makes hand-drawn SVG testable in node without adding jsdom, and it is the only plan that gives the stylesheet to exactly one wave. ## The seven bullets

1. **The paper is the spine, and the paper is arithmetic.** Every number that matters on this page — 132 positions at 10 cpi, 66 line positions, three lines per half-inch bar, 80 columns × 12 rows at 0.087/0.250 in pitch, matrix 30 and 35, twelve carriage channels, the five dualed chain glyphs — lives in a DOM-free module under `src/ui/period/paper/` or `src/ui/period/console/`, tested in node beside the core tests. The rule is literal and it is what makes hand-drawn art gateable without adding jsdom: **no number is computed in a file that touches the DOM.** Every `*View.ts` is an adapter that computes nothing.

2. **Two oracles the phase cannot fake, and one of them is free.** architecture.md §8's named Phase-4 oracle is the Exhibit II job log — and the test SLICES it out of `docs/research/console-and-physical.md` §2 at run time (the fence at lines 59/79, nineteen lines, the elided `D bbbb...` row excluded by name), the mechanism `test/rpg-columns-vs-research.test.ts` already ships. The free one: `renderGreenBar(paper, {chain:'A', formLines:66})` — Phase 2's, frozen, byte-gated by three existing page goldens — must equal the trimmed `\f`-joined output of the new `paginate()`. Two independent renderers over one paper. A restyle that breaks the paper breaks a golden.

3. **Zero core lines, and it is a `git diff` at every commit.** `git diff --stat <base>..HEAD -- src/core src/asm src/rpg src/formats` is empty at every wave. The three places the period surface is tempted are settled inside the UI with the core change costed and refused in §15: the 1403's A/H switch is a five-glyph restrike of the printed page (verified exact against `chainGlyph` over all 64 codes, because `Printer1403.chain` is `readonly` at printer1403.ts:366); the DISPLAY and C.E. detents type their `S` through `machine.stop()`, which is literally `{ fieldLine('S'); }` at machine.ts:380 — the same call `setMode` ends on at :327 — so **any** mode change types exactly one `S` (A22-0526-3 p.50, [verified]) with no `ConsoleMode` member added; and the inquiry hold lives in Phase 4's own animation frame, never in `step()`.

4. **Wave 0 is a move whose oracle is identity, not green.** `git mv` of `unitrecord/`, `autocoder/` and `rpg/` into `src/ui/period/` — the destination architecture.md §6 names and four shipped file headers promise. Its gate is `git diff -M --find-renames … | grep -v "from '../"` printing NOTHING, plus 93 files / 1745 tests / 1 skip, smoke 6 / 49, cc01 at 1241 instructions with the check at 00322, and 348 / 2251 / 3688 / 6982 bytes unmoved. The external surface of `src/ui` is exactly five functional references. `src/ui/internals/controls.ts` is byte-frozen at SHA-256 `a6d90f54c0649625dcf32161d12332dd867bf66a424752fcfc55b4bfd4bf318f`, written into both the test and §13.

5. **The carriage straddle is drawn, named on the page, and not fixed.** `straddled(from, to, tape)` is pure, and its wiring is written into the plan rather than guessed: `from` = the last printed position on the form, `to` = the final `snapshot().printer.carriage`. On `demos/cycle-probe` that is form 2 line 59 → line 61 across the channel-12 punch at 60, asserted alongside `carriage.channel12 === false` on the same frame, with `demos/sales-summary` asserted empty. Not a paper-only rule (form 2 prints nothing at 60 or 61), not a per-frame `CarriageState` diff (`START_BUDGET` is 2000 instructions), not a `PrintEvent[]` replay (the automatic single space emits no event). Recording rather than fixing is the `RW#` / `WM#` / `loader.ts:90` precedent.

6. **Typing at the 1415 becomes real; delivery stays queued.** The `^`-prefixed text box goes. In its place: a focusable Selectric with the drawn Fig.43 keyboard, a real WORD MARK key at the far left of the QWERTY row, backspace, INQ CAN, and a lock the program's read does not open — the operator's INQUIRY REQUEST does. The run loop is Phase 4's animation frame, so it holds from REQUEST to RELEASE, and the latch is the UI's own, never `Console1415.pendingRequest` (the device clears that inside `read()` and `precheck()`, so a loop gated on it deadlocks). `INQUIRY_ENTRY_IS_PRE_SUPPLIED` stays `true` with its scope narrowed and its wording amended in a dated `open-questions.md` section; a blocking `step()` is refused with its cost named.

7. **Seven waves, ~2,300 new + ~1,600 restyled source, ~640 CSS in ONE wave, ~2,200 test lines, three new goldens, zero new dependencies.** DECISIONS.md line 11 closes as **Vite `[settled]`** — `typescript ~5.9`, `vite ^8`, `vitest ^4`, unchanged — with exactly one config line added, `base: './'`, because the built page currently emits `src="/assets/…"` and will not open from the filesystem. No framework, no jsdom, no webfont, no CSS preprocessor, no audio. Five gate numbers move only where the plan says they move, and no byte of machine-produced text moves at all.

## Rulings where the judges disagreed

**Q. Does the phase move `src/ui/{unitrecord,autocoder,rpg}` into `src/ui/period/`?**

- Positions: paper-first and reuse-first both `git mv` in wave 0. operator-first declines, creating `src/ui/period/` as a NEW directory alongside the old blocks — and then has `src/ui/unitrecord/mount.ts` mounting `src/ui/period/reader1402View.ts`. Judge 2 flagged the structural inconsistency; judges 1 and 3 did not rule.
- **Ruling:** MOVE, in wave 0, alone, identity-gated.
- Basis: architecture.md §6 names the destination in its own heading text: '**Period surface** (`src/ui/period/`, Phase 4)'. Three shipped file headers promise it (`readerView.ts`, `printerView.ts`, `autocoder/mount.ts`, `sourceBox.ts` — 'Phase 4 moves this directory into src/ui/period/ and styles it; nothing here is thrown away'). Verified the external surface is five functional references, so the move's oracle can be identity rather than green.

**Q. How does the rotary type its `S` line on the two detents `ConsoleMode` cannot name?**

- Positions: operator-first routes DISPLAY and C.E. through `machine.stop()` and asserts one `S` per turn over all 30 ordered pairs. paper-first's `toMode('display')` returns `undefined` and the ledger accepts losing the line ('the observable difference is one S line'). reuse-first agrees with operator-first. Judge 2 called paper-first's version a fatal flaw; judge 1 scored it as a fidelity loss; judge 3 named the RUN→DISPLAY→RUN case as the exact bug a naive implementation ships.
- **Ruling:** Take operator-first's rule verbatim, and note that the loss is at least TWO lines, not one.
- Basis: machine.ts:325 is `if (next === machine.mode) return;` — so after a UI-only DISPLAY detent (which leaves `machine.mode === 'run'`) the turn back to RUN also types nothing. machine.ts:380 is `stop(): void { fieldLine('S'); }` and setMode ends on the same `fieldLine('S')` at :327, so the two paths are byte-identical on the paper. console-and-physical.md §4: 'Any change of the mode-switch setting — not only the STOP key — causes a stop print-out' [verified — A22-0526-3 p.50].

**Q. How is the carriage straddle derived so that `CARRIAGE_SENSES_AT_DESTINATION_ONLY` is visible?**

- Positions: operator-first: `crossedPunches(paper, tape)` — punched lines lying strictly between two consecutive PRINTED lines. paper-first: `straddled(from, to, tape)` as a pure function, with the page-side `from`/`to` taken by diffing `CarriageState` across animation frames. reuse-first: `replayCarriage(events, tape)` over `machine.printer.events`. All three judges attacked a different one.
- **Ruling:** Keep paper-first's pure `traversed`/`straddled` signatures. Wire them from (last printed position on the form, final `snapshot().printer.carriage`) — NOT from paper alone, NOT from a frame diff, NOT from `PrintEvent[]`.
- Basis: Verified by parsing `test/golden/cycle-probe.page.txt`: form 2 runs to 59 line positions and its last printed line is `LAST CARD` at form line 59; nothing prints at 60 or 61 — so operator-first's paper-only rule reports NOTHING on the one deck that exhibits the divergence, and its wave-4 gate cannot go green. `PrintEvent` is `{kind:'line',text} | {kind:'space',lines,afterPrint} | {kind:'skip',channel,afterPrint}` (types.ts:359-362) with no positions, and it is pushed in exactly five places (printer1403.ts:510, 577, 581, 585, 590) — the AUTOMATIC SINGLE SPACE emits none, so reuse-first's replay is structurally blind to it. `START_BUDGET = 2000` (machine.ts:45) merges motions inside one frame, so paper-first's own frame diff is unreliable on the page even when its node test passes.

**Q. Is the Phase-4 console golden authored, or read out of the research file?**

- Positions: operator-first hand-builds `test/fixtures/exhibit-ii.lines.ts` and freezes a golden it then compares against. paper-first authors the golden 'from the manual's own transcription and the Fig.5 matrix rule'. reuse-first slices the fenced block out of `console-and-physical.md` §2 at test time and names the elided row. Judges 1 and 3 both required reuse-first's mechanism.
- **Ruling:** Slice at test time. Drop the `D bbbb...` row by name in the test header. Compare with combining marks STRIPPED and the matrix indent OFF; assert the marks and the indent as separate rule-level cases.
- Basis: The fence at docs/research/console-and-physical.md lines 59/79 is 19 lines (not eighteen), contains ZERO combining marks (grepped for U+0300–U+036F), contains no blank line before the `S` line, and contains a literal elision `D bbbb...` that is not a renderable `ConsoleLine`. Meanwhile §2's layout table gives 'Normal stop → Spacing before: double' and 'underline any register field whose contents have bad or absent parity', and `formatPrintout` sets all four underline flags when `ch1Unit` is absent. So byte-equality with the manual's text and 'carries the underline and the double space' cannot both hold in one assertion. `test/rpg-columns-vs-research.test.ts` is the shipped precedent for slicing a research table at test time.

**Q. How many named human browser checks does the phase carry?**

- Positions: operator-first: six (B1-B6), including B5 for Phase 5's invalidation. paper-first and reuse-first: one (criterion 15b / 14b). Judge 3 called the six a regression against house precedent and noted B5 covers something node-checkable.
- **Ruling:** ONE named human criterion with an enumerated observation checklist inside it, recorded in `docs/BUILD-LOG-4.md` with the date and what was seen. Constraint 11 is asserted in node, not by eye. Separately — and this is new — each art wave carries an orchestrator screenshot check via `claude-in-chrome`, recorded in the build log, because no oracle in this phase can tell you the page looks like a 1415.
- Basis: phase-3-autocoder.md §13 criterion 11b and phase-5-rpg.md §13 criterion 13b are each a single named criterion described as the only one that needs a human at a screen; STATUS.md records 11b as 'run in Chrome by the main session'. The `stale` graft (below) removes B5's reason to exist.

**Q. Is Phase 5's invalidation (constraint 11) checkable in node?**

- Positions: reuse-first asserts it already is — '`createAutocoderSession().setSource(x)` leaves `hopperText()` empty until `assemble()` runs'. paper-first says no and adds ~16 lines of `stale` to `autocoder/session.ts`. operator-first hands it to a human (B5). Judge 3 verified reuse-first's assertion is vacuous.
- **Ruling:** Take paper-first's `stale`. `readonly stale: boolean` set by `setSource`/`setDataText`, cleared by `assemble()`, with `hopperText()` returning `''` while stale — adopting the shape `src/ui/rpg/session.ts` already ships.
- Basis: Verified in `src/ui/autocoder/session.ts`: `setSource(text) { source = text; }` does not touch `result`, and `hopperText()` returns `''` iff `result === undefined` — true of any fresh session regardless of `setSource`, and false after an assembly, where it returns the STALE deck. The real invalidation is `invalidateArtifacts` in `autocoder/mount.ts`, i.e. in the DOM. `rpg/session.ts:31` by contrast has `const invalidate = () => { result = undefined; }` called from `setSpecText`.

**Q. Are the rotary detent angles a fabricated constant?**

- Positions: Judge 1 called paper-first's `ROTARY_ANGLE` ({run:0, display:60, alter:120, ce:180, ieCycle:240, addressSet:300}) 'a [likely] ruling presented with a [verified] citation'. Judges 2 and 3 did not object.
- **Ruling:** Judge 1 is overstated. Keep the table; tag it `ROTARY_DETENTS_ARE_60_DEGREES_APART` as [likely]-derived-from-[verified], with the fallback 'read the angles off a Fig.47 scan if one is obtained'.
- Basis: console-and-physical.md §3 line 85 is [verified]: 'RUN at top, ADDRESS SET upper-left, DISPLAY upper-right, I/E CYCLE lower-left, ALTER lower-right, C.E. at bottom (clockwise from RUN: DISPLAY, ALTER, CE, I/E CYCLE, ADDRESS SET)'. Six named clock positions at 12, 2, 4, 6, 8 and 10 o'clock ARE 60° apart; the degree table is a faithful rendering of the figure's description, not an invention. What is genuinely unstated is the degree number, which is why it gets a constant and a fallback rather than a refusal.

**Q. Does the phase edit a research file?**

- Positions: reuse-first's wave 0 appends a dated `## 14. Phase 4 wave-0 primary read` section to `docs/research/console-and-physical.md` on a bounded two-attempt read of scanned manuals. Judge 1 called it fatal; judges 2 and 3 did not rule.
- **Ruling:** Keep the bounded read — it is the only proposal that tries to CLOSE gaps rather than fall back — but write its result to a dated Phase 4 section of `docs/research/open-questions.md` and to `docs/BUILD-LOG-4.md`. A correction to `console-and-physical.md` is a separate escalation commit the orchestrator approves. Fold the read into wave 0 alongside the move rather than spending a whole wave on it.
- Basis: DECISIONS.md 2026-08-31 records the escalate-don't-patch precedent (`RW#`, `WM#`, `loader.ts:90`); every Phase-3 and Phase-5 research finding landed in a dated `open-questions.md` section. `console-and-physical.md` currently ends at `## 13. Gaps and fallbacks` + `## Sources`; a half-succeeded read landing inside it makes its confidence tags unreliable for every later reader.

## Framework ruling (closes DECISIONS.md line 11)

**Close `docs/DECISIONS.md` line 11 as `[settled]`: Vite, minimal deps. Three devDependencies after Phase 4 — `typescript ~5.9.0`, `vite ^8.0.0`, `vitest ^4.0.0`, unchanged and verified against `package.json` — and exactly one line of build config added: `base: './'` in `vite.config.ts`. No framework, no jsdom, no webfont, no CSS preprocessor, no audio library.** Four concrete reasons, each checkable rather than aesthetic, and two of them Phase 4 creates rather than inherits. (1) **`?raw` is already load-bearing.** Every `sample …` button on the page is a Vite raw import of a file under `demos/` — verified at `deckBox.ts:14` (`hello-dad.cards?raw`), `sourceBox.ts:19-20` (`hello-dad.asm?raw`, `hello-dad.data.cards?raw`) and `specBox.ts:8-9` (`sales-summary.data.cards?raw`, `sales-summary.rpg?raw`) — three files, five imports. `demos/` deliberately sits outside `public/` because, as `deckBox.ts:7`'s own comment records, a fetch works under `npm run dev` and 404s in a `vite build` output. Replacing Vite means reimplementing `?raw` or moving the demo decks into `public/`, where they would be shipped assets rather than source. Note the trap the shims already document: an ambient module declaration is program-wide, and `autocoder/raw-import.d.ts`'s header records that re-declaring `*.cards?raw` from a second file merges into a duplicate `export default` and fails typecheck — which is why wave 0 MERGES the three shims rather than moving three of them. (2) **Phase 4 adds exactly one new build capability, a CSS import**, and Vite does it with zero config and zero dependencies; the only new file it costs is a four-line `declare module '*.css';`, folded into the merged shim, following the pattern the `?raw` shims already established because this repo carries no `vite/client` types (tsconfig.json's own header records that it carries no `@types/node` either and uses ambient shims instead). (3) **Vitest shares Vite's transform**, so one config and one toolchain covers 99 test files and the NodeNext `.js`-specifier resolution documented in `tsconfig.json` works identically in dev, in tests and in the build; a second pipeline is the alternative `architecture.md` §10 already priced. (4) **The deliverable is a static local site** (DECISIONS.md 2026-08-30, 'Run local, Gitea'), and this is the phase whose deliverable IS the built page — so it is the phase that must make `npm run build` produce something that actually opens. It does not today: I ran `npx vite build` and the emitted tag is `<script type=\"module\" crossorigin src=\"/assets/index-DzWn_BmX.js\">`, an absolute path that resolves to nothing under `file://`, and `vite.config.ts` has no `base` key. That one line is the phase's whole build change, and 'dist/index.html opens from the filesystem with no network request' becomes exit criterion 17. **No framework, and the reason is specific rather than doctrinal.** `architecture.md` §10 asked for a concrete reason if Phase 4 turned out to need one; it does not, and here is why in this codebase's own terms. The part of a framework this page needs is already written and already shipped: every view implements `render(s: MachineState)` behind a hand-written diff key — `readerView.ts:72-84` joins eight counts into one string, `printerView.ts:144-155` keys on paper length plus five carriage fields, `inquiryView.ts:64-74` on one boolean, `panel.ts:143-147` rebuilds the log only when its length changes. That is about ten lines a view and roughly 120 lines in total, it is what the frame gate at `mount.ts:28-37` was built around, and Phase 4's own new surfaces (the rotary, the keyboard, the light panel, the form) are pure functions of `MachineState` plus one local view-state value and follow the same pattern. A component framework would put a virtual-DOM reconciler on top of a diff that already works, in exactly the case §10 names as the one it helps least — six hand-drawn SVG panels with no shared reactive state and one 132-column `<pre>` that must not re-render every frame. **Also refused, each with its reason.** jsdom: a fourth dependency and a second vitest environment, and the design's own answer is better — no number is computed in a file that touches the DOM, so there is nothing a DOM test could assert that a node test cannot. A CSS preprocessor: ~640 lines of hand-written CSS with custom properties needs no nesting engine. A webfont: the slashed zero is the formatter's (`printout.ts:29`, C28-0351-5 p.2) and the word mark and parity underscore are combining marks, so `ui-monospace, Menlo, Consolas, monospace` renders everything the Selectric prints — and `⌑` and `‡` already render from that stack in shipped output; if a platform lacks either, draw two SVG paths rather than fetch a face into a local-first site. An audio library: sound is out on `[unverified]` grounds and would be a dependency for a claim we cannot make. **`package.json` gains no script and no dependency in this phase.**

## Residual risks

- **The art is gated by oracles that cannot see it.** Roughly 1,300 lines of hand-drawn SVG plus ~640 lines of CSS, produced by agents that render nothing. Every gate in this plan would go green on an ugly page, and the two things most likely to be wrong — the light panel's box order and proportions, and the desk's paper-order layout — are precisely what a table-fidelity test cannot judge. Mitigation is a per-wave orchestrator screenshot in `docs/BUILD-LOG-4.md`, which is new discipline for this project and unproven.

- **The 1415 keyboard fights the textareas.** A focusable Selectric that captures keystrokes shares a page with three `<textarea>`s (the source box, the spec box, the deck box). No architect said which element owns `keydown`, and a `document`-level listener will eat characters typed into the coding sheet. The plan must fix focus ownership at the console region and gate the keyboard on it; a builder who reaches for `document.addEventListener` will ship a page where the Autocoder source box silently loses keystrokes on the MACHINE ROOM tab.

- **The console golden's exclusion is a judgement call that can drift.** The Exhibit II block contains `D bbbb...`, a literal elision. The test excludes it by name in its header, which is honest — but a future reader who does not read the header may 'restore' it and produce a golden that asserts a line the manual never printed.

- **`paginate` and `renderGreenBar` could be made to agree by weakening `paginate`.** The cross-check is the phase's best free oracle precisely because the two renderers are independent; if a builder implements `paginate` by calling `renderGreenBar` and splitting, the assertion becomes a tautology and nothing catches it. The plan states the independence requirement; nothing enforces it mechanically.

- **The straddle derivation still under-reports.** Deriving from (last printed position, final carriage state) sees the cycle probe, but a crossing in the middle of a run — one motion of several, none of whose destinations printed — is invisible unless the view samples per frame, which `START_BUDGET = 2000` makes unreliable. Stated at the point of use, and the negative case on `sales-summary` keeps the derivation from silently reporting everything, but the page can still miss a crossing a person would want to see.

- **Two surfaces can still disagree about the mode.** `controls.ts` is byte-frozen and its `<select>` never re-reads `machine.mode`. Phase 4's live label above it tells the truth, but the frozen select sitting beside a correct label is itself confusing, and the only clean fix is an edit exit criterion 3 forbids.

- **`npm test` and `npm run smoke` both run `npm run oracles` first**, which downloads GPL oracle files into a gitignored `oracles/`. Every wave gate names those commands. The tiers that need the files skip with a clear message when the fetch fails, so a wave still gates offline — but the stated test COUNT moves, and a wave that reports a lower number because a download failed looks identical to a wave that lost a test.

- **Line estimates for art are the softest numbers in the plan.** ~1,290 lines in wave 5 alone (desk, mount, session, 640 CSS, both authoring stations restyled) is the largest single wave anyone proposed, and CSS is the one artifact with no test that judges its content. Splitting wave 5 is the obvious relief valve if it overruns, and the plan should say so before it does.

- **Phase 5's spec sheets stay textareas in a drawn frame.** This is the declared, refused fidelity gap. If Zarathustrum's real test of Phase 4 is 'does the Autocoder tab look like a 1410 coding sheet', this plan does not pass it, and that is better known at the ≤7-bullet gate than at criterion 19.
